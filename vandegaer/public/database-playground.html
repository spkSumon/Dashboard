🌟 Database Architecture

SocialBit uses a multi-tenant relational database architecture built on MySQL/MariaDB. The schema is designed for social media analytics with support for multiple platforms (TikTok, Instagram, Facebook, YouTube) and comprehensive metric tracking.

🎯 Key Design Principles

  • Multi-Tenancy: All data isolated by client_id with CASCADE DELETE
  • Time-Series Optimization: Partitioned metrics_history for performance
  • Data Lineage: Track all data sources (API, CSV, manual) with audit trail
  • Algorithm-First: 2026 metrics prioritize watch time, completion rate, saves
  • Cross-Platform: Unified schema supports all major social platforms

👁️ Database Views (Virtual Tables)

top_posts (VIEW) ▼
SQL Definition:
SELECT id, platform, post_type, topic, caption, posted_date, views, likes, comments, shares, saves, engagement_rate, (likes + comments + shares) as total_engagement FROM posts WHERE posted_date IS NOT NULL ORDER BY engagement_rate DESC LIMIT 100
Purpose: Quick access to top 100 best-performing posts across all platforms
platform_comparison (VIEW) ▼
SQL Definition:
SELECT platform, COUNT(*) as total_posts, AVG(views) as avg_views, AVG(likes) as avg_likes, AVG(engagement_rate) as avg_engagement_rate, SUM(views) as total_views FROM posts WHERE posted_date IS NOT NULL GROUP BY platform
Purpose: Compare performance across TikTok, Instagram, Facebook
hashtag_leaderboard (VIEW) ▼
SQL Definition:
SELECT hashtag, platform, total_posts, avg_engagement_rate, total_views FROM hashtag_performance ORDER BY avg_engagement_rate DESC LIMIT 50
Purpose: Top 50 hashtags ranked by engagement rate
client_overview (VIEW) ▼
Purpose: Multi-tenant dashboard showing all clients with their metrics
Shows: client name, connected accounts, total posts, views, likes, avg engagement, latest post date

Initial Database Schema
Core foundation: posts, users, metrics_history, hashtag_performance, post_hashtags, tiktok_demographics, import_history. Created analytics views: top_posts, platform_comparison, hashtag_leaderboard. Single-tenant POC architecture.
001
Settings Table
Added settings table for application configuration and API credentials.
002
Post Type & Topic
Added post_type (reel, story, post, carousel) and topic (promo, product, educational) columns to posts table for content categorization.
003
Content Planning
Created content_planning table for editorial calendar functionality. Schedule future posts with draft captions and hashtags.
004
Internal Fields
Added internal_caption and internal_notes to posts table. Internal tracking fields that don't modify live posts.
005
TikTok OAuth Tokens
Created tiktok_tokens table for OAuth 2.0 authentication. Store access tokens, refresh tokens, and expiration timestamps.
006
🌟 Multi-Tenant Foundation
MAJOR MIGRATION: Added clients, social_accounts, content_groups tables. Updated posts with client_id, social_account_id, content_group_id. Created default client for existing data. CASCADE DELETE for data isolation. Created client_overview and top_posts_by_client views.
007
Analytics Enhancement
Enhanced analytics capabilities with improved indexing and performance optimization.
010
Multi-Tenant Performance
Performance optimization for multi-tenant queries. Added composite indexes on (client_id, platform, posted_date) for faster filtering.
011
🚀 2026 Algorithm Metrics
CRITICAL UPDATE: Added watch_time, completion_rate, sends_count, profile_visits, skip_rate, duration columns to posts. These metrics are algorithm priority in 2026 (watch time > vanity metrics).
012
Hashtag Tracking System
Enhanced hashtag_performance table with tracking capabilities. Generate hashtag recommendations based on historical performance. Track usage trends and ROI.
013
Competitor Analysis
Created competitors and competitor_metrics tables. Track up to 5 competitors per client. Daily snapshots of competitor performance for benchmarking.
014
Website Traffic Correlation
Created post_website_traffic table. Link Fathom Analytics referral data to specific posts. Show which posts drive website visits and conversions.
015
Data Lineage Tracking
Created data_lineage table for audit trail. Track all data sources (API, CSV, manual) with timestamps. Multi-source conflict resolution with priority hierarchy.
016
Google Business Integration
Created google_business_locations and google_business_metrics tables. Track local business stats, reviews, Q&A, search appearances, actions (calls, directions, website clicks).
017
Database Optimization & Website Analytics
Added fathom_sites table for website analytics integration. Database optimization with improved indexes and query performance.
018
⚡ Metrics Partitioning
PERFORMANCE: Partitioned metrics_history table by month (snapshot_date). Dramatically improves time-series query performance for large datasets. Added client_id to metrics_history for multi-tenant isolation.
019
Glossary System
Created glossary_terms and glossary_term_links tables. Help non-technical users understand metrics with plain language definitions, formulas, and examples. Auto-link terms in UI.
020
💬 Unified Inbox
Created inbox_messages and message_threads tables. Unified inbox for all platform messages (DMs, comments, mentions). Track read status, reply timestamps, and conversation threads.
